# X68000 MicroPython + ulab — 機能・制限一覧

> **検証対象:** X68000向けカスタムMicroPython + ulab `6.11.0-2D-c`  
> **記録更新日:** 2026-11-25  
> **位置づけ:** 2026年11月に実施した簡易動作テストの結果。**NumPy互換性や全入力範囲での正常動作を保証するものではありません。**

このページは、X68000向けカスタムulabで「実際に何が動いたか」と「既知の制限」を整理したものです。実装済みの機能と、今回のテストで動作確認した機能は必ずしも同じではありません。

## 判定の見方

- **確認済み**：今回の小規模テストで実行でき、確認した値が期待値と一致。
- **部分対応**：特定の入力では動作するものの、対応範囲に制限がある。
- **既知の問題**：誤った値や例外を確認。利用時に注意が必要。
- **未検証**：名前の存在や過去の記録は確認できるが、今回の機能テストでは動作を確かめていない。

## 既知の問題と制限

### 1. 非連続配列の `reshape()` が誤った値を返す（要修正）

```python
from ulab import numpy as np

a = np.array([[1., 2., 3.], [4., 5., 6.]], dtype=np.float)
b = a.T.reshape((6,))
# 期待するC-order順: [1, 4, 2, 5, 3, 6]
# 現行のテストでは2番目の値が4ではなく2になった
```

**例外を出さずに誤った値を返すため、特に注意してください。** 転置やスライスによる非連続配列に対して、直接`reshape()`する操作は避けてください。原因はstride／連続性の扱いにあると推定していますが、修正と再テストは未実施です。

今回のテストで確認した範囲では、先に`flatten()`でコピーしてから変形する方法が候補です（追加のメモリを消費します）。

```python
flat = a.T.flatten()          # [1, 4, 2, 5, 3, 6] は確認済み
b = flat.reshape((2, 3))     # 連続した実数配列をreshape
```

### 2. complex ndarray に対する `flatten()` が失敗する

```python
from ulab import numpy as np

a = np.array([[1+2j, 3+4j], [5+6j, 7+8j]], dtype=np.complex)
a.flatten()  # TypeError: can't convert complex to float
```

複素数配列の生成、加算、乗算、`np.abs()`は今回の別テストでは成功しています。`flatten()`内部のdtype処理は要調査です。

### 3. 現在確認した非対応・制限

- **3次元配列：** `np.zeros((2, 2, 2))` → `TypeError: too many dimensions`。今回の構成は2次元まで。
- **1D×2D行列積：** `vector @ matrix` → `ValueError: matmul: only 2D arrays supported`。
- **`repeat(axis=...)`：** キーワード引数で`TypeError`。axisなしの繰り返しのみ動作確認。
- **誤った形状指定：** 要素数不一致のreshape、行列積の不整合なshapeは、それぞれ`ValueError`で拒否された。
- **一般的なNumPy互換：** dtype推論、各種ブロードキャスト、負のstride、0次元配列、高次元演算などは未検証。

## メモリ確保テスト

テスト時のGC空きメモリは約1,022,640バイト。以下は各サイズを**単独で**確保・先頭末尾へアクセス・解放した結果です。

| float32配列 | 配列データ本体のサイズ | 結果 |
|---|---:|---|
| 32×32 | 4 KiB | PASS |
| 64×64 | 16 KiB | PASS |
| 128×128 | 64 KiB | PASS |
| 256×256 | 256 KiB | PASS |

今回の実験では、確保した配列を解放した後のGC空きメモリは概ね開始時の水準へ戻りました。ただし、**512×512は今回の条件ではテストしておらず、最大確保サイズ・長時間動作・断片化耐性は未検証**です。搭載メモリやヒープ設定によって結果は変わります。

## 動作確認の方法

今回使用したスクリプト（リポジトリへの収録・配置先はtests/）：

- `ulab_capability_check.py`：基本機能17項目。**17項目が実行でき、例外0件**。このうち1項目はAPI名の存在確認のみ。
- `ulab_limits_check.py`：境界・制限22項目。**PASS 13 / LIMIT 4 / FAIL 1 / INFO 4**。
- `ulab_memory_probe.py`：float32配列の32×32～256×256の確保と境界アクセス。

実行結果はそれぞれ`ulabtest.txt`、`ulablimits.txt`、`ulabmemory.txt`に記録。各テストは少数のサンプルについての確認であり、網羅的な回帰テストではありません。

## 更新方針

新しい環境やパッチで動作確認したら、この一覧に「確認したAPI」「テスト条件」「期待値との差」「既知の制限」を追記します。**既存ulabの機能をビルド時に有効化したものと、X68000向けの独自変更・修正は、今後ソース差分に基づき別途整理する予定です。**
